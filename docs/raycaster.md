# Raycaster — вид від першої особи (псевдо-3D)

## Що це

Опційний режим рендеру: той самий 2D-світ (сітка стін `tileMap` + вороги) показаний
**від першої особи**, як у Wolfenstein 3D (id Software, 1992). **Симуляція й ШІ не
змінюються ні на рядок** — це суто інший спосіб намалювати ті самі дані.

Перемикач: клавіша **F** (вид зверху ↔ від першої особи). Прапорець-стан — `Game.firstPerson`.

## Ідея (та сама, що й whiskers ШІ)

`wallWhisker` марширував ОДИН промінь по `tileMap` до стіни (зір агента). Тут — по
одному променю **на кожну колонку екрана** в межах поля зору (FOV):

```
для кожної колонки x:
  промінь під своїм кутом → DDA-марш по сітці до стіни → відстань d
  висота смуги = screenHeight / d   (ближче → вища)
  затемнення ∝ d                    (далі → темніше)
```

Багато променів + вертикальні смуги = ілюзія коридорів.

## Ключові прийоми

- **DDA** (`castColumn`) — марш не по пікселях, а від грані до грані сітки: один
  крок = одна клітинка → до стіни за ~десяток кроків (швидко). Повертає
  перпендикулярну відстань (без «риб'ячого ока») і чи це **межа рівня**.
- **Камерна площина** — промені задаються як `dir + plane·cameraX`, що автоматично
  дає перпендикулярну відстань (fisheye-корекція не потрібна).
- **Вороги-спрайти** (`drawSprites`) — білборди: кожного ворога переводимо в
  систему координат камери (інверсна матриця `[dir|plane]`), розмір ∝ 1/глибина,
  малюємо вертикальними смугами з тестом глибини проти **z-буфера** стін (спрайт
  за стіною не малюється). Сортування далеко→близько (painter's).
- **Межа рівня** — бурштиновий колір (у 3D) і рамка (зверху): позначає край, крізь
  який гравець «протікає» (wrap-around).

## Керування (у виді від першої особи)

| Клавіша | Дія |
|---|---|
| ← / → (A/D) | поворот камери (`camAngle`) |
| ↑ / ↓ (W/S) | рух уперед/назад у напрямку погляду |

Фізика (тертя, стіни, wrap) — та сама, що у виді зверху; змінюється лише те, як
клавіші перетворюються на прискорення (`handleFirstPersonInput`).

## Що покращено (після переходу на бойову механіку)

| зміна | ефект |
|---|---|
| `rayColW` 4 → **1** | піксельний край замість сходинок по 4px |
| небо й підлога **градієнтом** | глибина замість двох плоских заливок |
| туман до кольору **горизонту** | далина читається як «далеко», а не «темно» |
| спрайти: градієнт + смужка HP | юніт перестав бути плиткою кольору |

**Про туман окремо.** Раніше затемнення вело колір **у чорне** (`shade` до 0.15) — і
далина читалась як «темно». Тепер веде **до кольору горизонту**, у якому розчиняються й
небо, і підлога: сцена змикається в одну атмосферу. Формула та сама, ціль інтерполяції
інша, вартість **нуль**.

**Про вартість.** 1700 променів × ~10 кроків DDA = ~17 тис. операцій за кадр — дрібниця.
Дорогими стали б **спрайти**: один прямокутник на колонку дав би 400 викликів на
близького юніта. Тому `drawSprites` іде колонками й накопичує **суміжні видимі**,
малюючи кожен пробіг разом. Видимість міняється лише на краях стін, тож пробігів
зазвичай один-два: `400 → ~6-12`.

Тобто чіткість зросла вчетверо, а спрайти стали **дешевшими**, ніж були.

**Смужка HP у 3D потрібніша, ніж зверху:** там стан юніта видно по ворсу, кольору й формі
тіла, а тут — ніяк інакше.

# AI Brain: ворог-учень (v3 — Q-learning + whiskers)

## Що це

Ворог типу `ConfigLearner` (прапорець `IsLearner`, зелений) керується
**нейромережею, що вчиться сама через reinforcement learning (Q-learning)**.
У нього **немає вчителя** — ніхто не каже правильний рух. Агент діє, отримує лише
**reward** (нагороду/штраф) і сам відкриває стратегію: переслідувати гравця й
обходити стіни.

> **Важливо:** мозок вмикається прапорцем `IsLearner: true` у `UnitConfig`, а
> НЕ міткою `Label` (мітка — лише для відображення). Це дозволяє назвати ворога
> як завгодно, не ламаючи навчання.

> Еволюція мозку:
> - **v1** — одношаровий перцептрон (лінійний, імітував chase-формулу).
> - **v2** — MLP + backprop, supervised: вчитель казав точну відповідь (перехоплення).
> - **v3** — Q-learning: вчителя немає, лише reward. Чесний шлях для обходу стін.

---

## Supervised vs Reinforcement Learning

```
supervised (v2):  "правильний рух = (0.83, 0.55)"   ← ми знаємо ціль
RL (v3):          "ти зробив дію 3 → отримав +0.5"  ← знаємо лише оцінку
```

Аналогія: ти не показуєш собаці, які м'язи напружити, щоб сісти — ти даєш
смаколик, коли вона сіла. Собака сама зв'язує дію з нагородою. Це і є RL.

## Архітектура (Q-мережа з пам'яттю)

```
 вхід = стек кадрів (64)   hidden1(32)   hidden2(16)   Q(8)
  напрямок, відстань     ─┐   ┌──◯──┐      ┌──◯──┐      Q[N] ↑
  швидкості, 8 whiskers   ├─W1►│tanh│──W2──►│tanh│──W3─► Q[E] ← argmax
  × stackFrames кадрів   ─┘   └──◯──┘      └──◯──┘      ...
                              (згин 1)     (згин 2)   (лінійний зріз)
```

- Вхід — **стек останніх `stackFrames` кадрів** (памʼять), разом **64** числа.
- **Два приховані шари** (tanh) — «згин, потім згин ще раз» простору входів
  (глибина ефективніше вичленяє складні залежності, ніж один ширший шар).
- Вихід — **8 Q-значень** (лінійні). **Дія** = `argmax Q`.

> Еволюція входу: 1 кадр без памʼяті → стек кадрів (памʼять). Еволюція глибини:
> 1 прихований шар → 2 (детальніше в секціях «Памʼять» і нижче).

> **Альтернативна памʼять — GRU** (прапорець `useGRU`, дефолт): замість стеку кадрів
> на вхід іде ОДИН кадр (16), а «минуле» живе в рекурентному стані `h`, який мережа
> несе між кадрами й **сама** вчиться, що тримати. Деталі — секція «RNN/GRU».

### Три файли мозку

Код розділено за ролями — відкривши файл, одразу видно, у якому ти світі:

| Файл | Що містить |
|---|---|
| `brain.go` | **спільне ядро**: константи, `Net`/`Brain`, активації, ε-greedy, `rewardFor`, вуса й зір, збереження ваг, **диспетчери** `Step`/`train` |

| `brain_gru.go` | шлях **GRU** (`useGRU=true`): `forwardGRU`, `tdUpdateSeq` (BPTT), `stepGRU` |

## Стан (inputs)

### Один кадр — `baseInputs` (16)

Розмір кадру **спільний для всіх типів мозку**, але СЕНС слотів різний — кожен тип
кладе туди своє. Індекси іменовані (`inWhisker0`, `inVisible`, …), а не «магічні
числа»: інакше зміна `baseInputs` тихо ламає читання (ми вже на цьому попались —
`visible` читався як `cur[baseInputs-1]` і поїхав би на чужий слот).

```
             РІЙ (GatherInputs)              ВБИВЦЯ (GatherKillerInputs)
[0,1]        напрямок до гравця ─┐           напрямок FLOW-FIELD (крізь стіни)
[2]          відстань по прямій  │ 0, коли   відстань ПО ЛАБІРИНТУ
[3,4]        швидкість ГРАВЦЯ    │ не видно  ВЛАСНА швидкість
[5..12]      8 whiskers (завжди) ┘           8 whiskers (завжди)
[13]         visible: 1 = видно              швидкість цілі X
[14]         —                               швидкість цілі Y
[15]         —                               власне HP / MaxHP
```

Рій — **реактивний і частково сліпий** (POMDP): позиційні входи обнуляються, коли
гравця не видно. Вбивця — **всевидющий і знає лабіринт**: у нього немає `visible`,
бо flow-field глобальний. Деталі — секція «Вбивця» нижче.

### Повний вхід — стек кадрів (`GatherInputs` дає один кадр, `Step` склеює стек)
У стек-режимі мережа отримує **стек останніх `stackFrames` кадрів**, семпльованих
кожні `stackSkip` кадрів. Поточний кадр — перший у стеку, тож whiskers лишаються на
`inWhisker0..+7`. Деталі — секція «Памʼять і локальне сприйняття».

### Whiskers (сенсори стін) — `wallWhisker`

8 променів з центру ворога у напрямках компаса (ті самі 8, що й дії). Кожен
крокує до стіни (`isWallAt`) і повертає **близькість**: `1` = стіна впритул,
`0` = чисто на всю довжину (`whiskerRange ≈ 140px ≈ 5 тайлів`). Так мережа
«бачить» перешкоду ще до зіткнення.

---

## Дії (actions)

8 напрямків руху за компасом (екранні координати, y вниз):

```
0=N(↑) 1=NE 2=E(→) 3=SE 4=S(↓) 5=SW 6=W(←) 7=NW
```

`dirs8[action]` — одиничний вектор; рух = `Acc += dirs8[action] · brainForce`.
Whisker[i] і action[i] дивляться в один бік → мережа бачить, наскільки
заблокований кожен напрямок, у який може піти.

---

## Reward (нагорода) — три складові

```
reward  = (prevDist − dist) · rewardCloserScale       // наблизився → +, віддалився → −
if hitWall:  reward += rewardWallHit                   // удар об стіну (РІДКИЙ сигнал)
reward += rewardNearWall · whisker[обраний напрямок]   // близькість стіни (ЩІЛЬНИЙ сигнал)
```

**Рідкий vs щільний штраф за стіни** — ключова ідея:

| Сигнал | Коли | Навіщо |
|---|---|---|
| `rewardWallHit = -1.0` | лише в момент **удару** | груба ознака «так не можна» |
| `rewardNearWall = -0.3` | **щокадру**, ∝ близькості стіни попереду | плавний градієнт «тримай дистанцію» |

Аналогія: `rewardWallHit` каже «погано» лише коли ти **врізався**; `rewardNearWall`
— стіна «гріється» в міру наближення, тож агент **завертає заздалегідь**. Щільний
сигнал дає мережі градієнт, по якому вона вчиться **плавно обходити**, а не
довбати стіну (звідси «течуть як вода»). Прогрес до гравця (+) перебиває
proximity-штраф у проходах, тож щілини агент усе одно використовує.

> Reward shaping загалом: замалий reward тоне в шумі (мережа не вчиться),
> завеликий — дестабілізує. Масштаби підібрані так, щоб «хороший» кадр давав ~0.5.

> **Знак нагороди** керується прапорцем `Brain.flee`: хижак (`flee=false`) отримує
> `+` за **наближення**, жертва (`flee=true`) — той самий член зі знаком `−`, тобто
> `+` за **віддалення**. Штрафи за стіни знак НЕ міняють (врізатись погано обом).
> Це і є вся різниця між хижаком і жертвою — див. «Self-play» нижче.

## Навчання: Q-learning + рівняння Беллмана — `tdUpdate`

Q(s, a) = «наскільки хороша дія a у стані s» = очікувана сумарна майбутня
нагорода. Оновлюємо за **рівнянням Беллмана**:

```
target  = reward + γ · max_a' Q(nextState, a')   ← ціль
tdError = target − Q(state, action)              ← наскільки помилились
```

Далі — звичайний backprop `tdError`. **Тільки** для дії, яку реально зробили
(лише про неї маємо reward); інші виходи не чіпаємо.

`γ` (discount) розв'язує **credit assignment** (хто винен за відкладену
нагороду): цінність *просочується назад* у часі, крок за кроком.

## Три стабілізатори DQN (чому онлайн нейро-Q-learning без них падає)

Нейромережа + бутстреп (ціль залежить від самої мережі) + кореляція даних =
«смертельна тріада». Без захисту агент **колапсує** в одну й ту саму дію. Три
прийоми з DQN роблять навчання надійним:

| Прийом | Проблема, яку лікує | Як |
|---|---|---|
| **Target network** | Ціль `max Q(s')` тікає з кожним кроком (мережа женеться за хвостом) | Окрема ЗАМОРОЖЕНА копія ваг (`tW1/tW2…`) рахує ціль; синхронізуємо раз на `qTargetSync` |
| **Experience replay** | Сусідні кадри майже однакові → перенавчання на свіже, забування старого | Кільцевий буфер переходів; щокадру вчимось на ВИПАДКОВІЙ вибірці (`qBatch`) |
| **Error clipping** | Рідкісна велика похибка → велетенський стрибок ваг | `tdError` обрізаємо до `[-1, 1]` (Huber-подібно) |

Тест `TestQLearningChasesNoWalls` стабільно проходить (узгодженість дії з
напрямком до гравця 0.7–1.0 на десятках запусків).

## Anti-stuck — вихід із пасток

Навчання не ідеальне: іноді агент застрягає (б'ється в стіну або притиснутий у
куті). Механізм «фрустрації» — **рятівна сітка** поверх навчання:

**Два тригери застрягання** (накопичуються в `stuckCounter`):
1. **удар об стіну** (`hitWall` → `+stuckHitInc`);
2. **притиснутий до стіни без прогресу** (`maxWhisker ≥ stuckNearWall` і дистанція
   до гравця не зменшується → `+stuckNoProgInc`).

**Направлений вихід** — коли `stuckCounter ≥ stuckLimit`, на `frustrationFrames`
кадрів вмикається фрустрація: агент іде в **найвідкритіший бік** (`escapeAction`
обирає whisker з найменшою близькістю стіни), а не смикається випадково. Серед
однаково відкритих напрямків — рівноймовірно (щоб агенти не злипались в один бік).

> ⚠️ Це **сітка безпеки, а не лікування**. З майже нульовою ε жадібна політика
> може повести агента назад у ту саму кишеню. Справжнє лікування — щоб мережа
> *вивчила* не лізти туди (це робить `rewardNearWall` з часом).

## Феромони фрустрації (стигмергія)

Друга «сітка безпеки» — колективна пам'ять рою. Це **не** pathfinding (мозок так
само не знає мапи), а комашина **стигмергія**: агенти лишають у середовищі сліди, і
рій сам обтікає глухі місця.

- **Deposit** — коли учень ОФІЦІЙНО застряг (`markStuck` при спрацюванні фрустрації),
  у його клітинку сітки `g.frustration` додається `frustrationDeposit`. Саме при
  застряганні, а **не** на кожен дотик стіни — інакше виходив би «слимачий слід»
  уздовж усіх стін.
- **Decay** — щокадру вся сітка множиться на `frustrationDecay` (<1), тож «погане
  місце» з часом забувається й знову стає прохідним.
- **Repulsion** — у `calcAcceleration` учень читає сліди навколо (`frustrationForce`,
  радіус `frustrationRadius`) і отримує силу геть від них (× `frustrationRepel`).

Ефект: коли рій пілиться в куті — клітинки наливаються слідом → агентів виштовхує
назовні → вони розповзаються шукати інші входи. Один застряг — попередив усіх.
Емерджентний обхід з флангів, як у мурах.

> **Перемикач:** `pheromonesEnabled` (main.go) вмикає/вимикає всю стигмергію
> (deposit + repulsion + теплокарту). `false` → чистий Q-learning + whiskers +
> індивідуальний anti-stuck, без колективної пам'яті — для порівняння поведінки.

> Чому захардкоджено, а не вивчено: користь сліду надто відкладена в часі (уникнув →
> рій розповзся → хтось знайшов вхід → спіймав), а короткозорий реактивний агент
> такий довгий причинний ланцюг не вловить. Хардкодимо те, що знаємо й що RL не
> витягне дешево.

## Exploration: ε (постійна + опційний автоспад)

`ε-greedy`: з імовірністю ε — випадкова дія (дослідження), інакше `argmax Q`.

- **За замовчуванням ε ПОСТІЙНА** = `qEpsilonConst` (перемикач
  `epsilonDecayEnabled = false` у `main.go`). Стабільний рівень дослідження весь час.
- **Опційний автоспад** (`epsilonDecayEnabled = true`): ε лінійно спадає
  `qEpsilonMax → qEpsilonMin` за `qEpsilonDecay` кроків (поле `age` лічить кроки).
  Свіжий мозок багато досліджує → з часом стає мисливцем, але не нижче floor.
  Завантажений мозок стартує одразу на floor (`age = qEpsilonDecay`) — вже навчений.

## Цикл кадру (інтеграція)

```
Update():
  calcAcceleration()   ПАРАЛЕЛЬНО (на кожного учня з Brain != nil):
      1. state := GatherInputs(e, player)              // + whiskers
      2. action := Brain.Step(state, dist, HitWall)
           ├─ reward за минулу дію → net.remember(перехід)   // у буфер (під мютексом)
           ├─ оновити stuckCounter (anti-stuck)
           └─ обрати дію: фрустрація(escapeAction) / ε-greedy
      3. Acc += dirs8[action]·brainForce  (+ феромонне відштовхування)
  trainBrains()        ОДНОПОТОКОВО: кожну унікальну мережу — net.train(qBatch)
  updateUnits()      рух, відбивання, HitWall, deposit/decay феромонів
```

> Важливо: `Step` більше **НЕ тренує** — лише кладе досвід у буфер. Навчання
> винесене в окрему ОДНОПОТОКОВУ фазу `trainBrains()` (раз/кадр на мережу).

## Спільний мозок (вулик-розум)

Архітектуру розділено на дві сутності:
- **`Net`** — сама мережа: ваги + target + буфер досвіду + `sync.Mutex`. Може бути СПІЛЬНОЮ.
- **`Brain`** — «голова» одного ворога: указник на `Net` + ОСОБИСТА пам'ять (стан у
  часі, лічильники застрягання, `age`). Агенти діють індивідуально, а вчаться в
  (можливо) спільну мережу.

Прапорець **`sharedBrain`** (main.go):
- `false` — кожен учень має власний `Net` (рій РІЗНИХ особин: повільніше, різноманітно);
- `true` — усі ділять ОДИН `Net` (**вулик-розум**): N агентів наповнюють спільний
  буфер → колективний досвід → навчання **в рази швидше**; усі узгоджені (рухаються
  «ключами», як хижі птахи). Платня — зникає індивідуальність (усі думають однаково
  → можуть скупчуватись; це й лікують феромони — анти-стадність).

Навчання спільної мережі — **раз/кадр** (qBatch оновлень на ВЕСЬ рій, а не N×qBatch):
агенти лише наповнюють буфер, тренує `g.trainBrains()` централізовано.

### Паралелізм і безпека пам'яті (горутини)

`calcAcceleration` рахується **паралельно** воркер-пулом: `runtime.NumCPU()` горутин
(`sync.WaitGroup` + `wg.Wait()`), кожна — свій шматок ворогів `[start:end)`.

| Дані | Читання | Запис | Захист |
|---|---|---|---|
| `boidMap`, `frustration` | паралельно | однопотоково (інша фаза) | розділення фаз |
| `Net` ваги | паралельно (forward) | однопотоково (`trainBrains`) | розділення фаз |
| `Net.replay` (СПІЛЬНИЙ буфер) | — | **паралельно** (`remember` з багатьох горутин) | **`sync.Mutex`** |
| `Brain`-пам'ять, `units[i].Acc` | — | одна горутина на агента | власність |

Ключ: майже все безпечне через **розділення фаз** («всі читають → потім один пише»).
Єдине місце зі справжнім одночасним записом — **спільний буфер досвіду** (у нього
пишуть багато горутин у паралельній фазі) → саме його стереже `Net.mu`. Секція під
замком крихітна (один append) → контенції майже нема. Ваги лишаються лок-фрі: forward
читає в паралельній фазі, `train` пише в однопотоковій.

## Self-play (арена «хижак vs жертва»)

Досі рій вчився ловити або людину, або нерухому/скриптовану ціль. **Self-play** —
коли гравцем теж керує нейромережа, яка вчиться **тікати**. Обидві сторони
навчаються одночасно й тиснуть одна на одну → **co-evolution** (гонка озброєнь):
рій вчиться ловити не манекен, а супротивника, що активно уникає. Це той самий
принцип, що й у AlphaZero — сила зростає з гри проти себе.

**Уся хитрість — в одному знаку.** Мозок-жертва має ту саму архітектуру
(56→32→16→8, frame-stacking, DQN-стабілізатори), відрізняється лише прапорцем
`flee = true`, який інвертує член нагороди за дистанцію (див. розділ «Reward»).
Ніякого окремого коду поведінки — «тікай» випливає з перевернутого reward.

Прапорець **`aiPlayer`** (main.go):
- `false` — гравцем керує **людина** (клавіатура), як завжди;
- `true` — гравець отримує власний `NewBrain()` з `flee = true`; клавіатура
  ігнорується, рухом керує `updatePrey()`.

Що специфічне для жертви:
- **Вхід** — `GatherPreyInputs`: напрямок і швидкість **найближчого хижака** +
  8 whiskers на стіни (той самий DDA-зір) + `visible`. Дзеркало входу хижака.
- **Спіймали → не game over, а respawn.** `checkCollisions` у режимі `aiPlayer`
  викликає `respawnPlayer()` (випадкова відкрита клітинка, скид `hasPrev`, щоб не
  вчитись на «телепорті»). Тренування не переривається — арена крутиться далі.
- **Мережа жертви ефемерна** — тренується щокадру (`player.Brain.net.train`), але
  **не зберігається** (`saveBrains` пише лише хижаків). Self-play — це режим
  тренування рою; людина потім грає проти вже навченого рою.

> Межа екрану для гравця — **суцільна стіна** (без wrap-around): врізавшись,
> гравець зупиняється й отримує `HitWall`. Інакше жертва вивчила б експлойт
> «втекти крізь край карти» замість чесного уникання.

Для Learner-а малюються:

## Памʼять і локальне сприйняття (POMDP)

Два кроки, що наблизили агента до «справжнього» ШІ.

### Локальне сприйняття (`localSight`)
Раніше агент був майже всевидющий (`dx/dy` завжди). Тепер (якщо `localSight`) він
«бачить» гравця **лише в межах `sightRange` і по прямій видимості** (промінь не за
стіною — `hasLineOfSight`). Поза цим — позиційні входи = 0, `visible = 0`. Це
**часткова спостережуваність (POMDP)**: агент часто НЕ знає, де гравець.

### Памʼять (frame-stacking)
Щоб діяти при частковій спостережуваності, потрібна памʼять. На вхід йде **стек
останніх `stackFrames` кадрів** (семпли кожні `stackSkip` → вікно ≈ 0.5с). Коли
гравець зникає з очей, у стеку ще лишається кадр «щойно був отам» → мережа може
**продовжити переслідування за ріг**, а не забути миттєво.
- `stackFrames = 1` → памʼяті нема (реактивний агент-амнезик, базлайн);
- `stackFrames = 4` → короткочасна памʼять.

Памʼять — у кожного агента **своя** (`Brain.frames`); політика (`Net`) спільна.

> Це дешева памʼять (стек кадрів на feedforward-мережі). Її стеля: за межами вікна
> інформації **нема** (кадри «викотились»), а розтягувати вікно — грубо й дорого.
> Наступний щабель — **RNN/GRU** (реалізовано, нижче).

## RNN/GRU — справжня (вивчена) памʼять

Frame-stacking — це памʼять, яку задали **ми** (жорстке вікно `stackFrames×stackSkip`).
GRU — памʼять, яку мережа **вчиться сама**: несе між кадрами рекурентний прихований
стан `h` (вектор `gruHidden`=32) і сама вирішує, що в ньому тримати й **як довго**.
Вмикається прапорцем **`useGRU`**; співіснує зі стек-режимом (перемикач у рантаймі).

### Клітина GRU (`forwardGRU`)
Вхід — ОДИН кадр `x` (14) + старий стан `h`. Три ворота вирішують оновлення памʼяті:
```
z  = σ(Wz·x + Uz·h + Bz)          update gate — скільки нового пускати
r  = σ(Wr·x + Ur·h + Br)          reset  gate — скільки старого забути
h~ = tanh(Wh·x + Uh·(r⊙h) + Bh)   кандидат нового стану
h' = (1−z)⊙h + z⊙h~               новий стан (інтерполяція старе↔кандидат)
q  = Wq·h' + Bq                   Q-значення (лінійно)
```
`h` — у кожного агента **свій** (`Brain.h`, несеться між кадрами, скид на respawn);
ваги GRU — **спільні** в `Net` (вулик лишається).

### Навчання — BPTT (backprop through time)
Рекурентну мережу не навчиш на окремих кадрах — треба **послідовності**:
- **sequence-replay**: буфер зберігає відрізки по `seqLen`=8 поспіль кадрів одного
  агента: `seqBurnIn` кадрів прогріву + `seqLen` навчальних (`sequence`: `x[],a[],r[]`
  + `xEnd`). Агент накопичує відрізок у `Brain` і віддає в спільний `Net.seqReplay`.
- **`tdUpdateSeq`** (BPTT) у 3 фази: (1) forward живої мережі по відрізку з кешем
  усіх проміжних (`z,r,cand,h`); (2) Беллман-ціль по target-мережі; (3) backprop
  **крізь час** — помилка на `h_t` = з виходу цього кроку + з рекурентного звʼязку
  наступного. Ланцюгове правило тепер іде не лише крізь шари, а й **уздовж часу**.
- Захист: error-clip ±1 (як у стеку) + **кліп градієнта в часі** (`gruGradClip`)
  проти вибуху при розгортанні.

### Результат (виміряно)
Ворог, втративши гравця з очей, **тримає курс** на останню бачену точку й агресує
з-за рогу — поведінка, недосяжна для frame-stacking (його памʼять вивітрювалась).
Метрика `blind-chase` вперше **зрушила**: ~61% (GRU) проти ~55% (стек) — ефект
памʼяті став достатньо великим, щоб проявитись у числах, а не лише візуально.

> **Burn-in (проти stored-state problem):** replay стартує з `h=0`, але це не той `h`,
> що агент реально має під час дії (той накопичений за сотні кадрів). Тому перші
> `seqBurnIn`=4 кадри кожного відрізка — **прогрів**: лише forward, без loss/градієнтів,
> щоб `h` став реальним ПОТОЧНИМИ вагами; loss+BPTT — лише на навчальному вікні
> `seqLen`=8. Стан на момент обрахунку помилки близький до бойового → точніше навчання.
> (Ваги GRU **зберігаються** — див. секцію «Збереження ваг».)

> **Стабільність (спостережений дрейф і як приборкали):** при довгому онлайн-навчанні
> рекурентна політика **повільно розбігалась** — `maxQ` повзла вгору, крива reward
> розгойдувалась, рій вироджувався (збивався до стіни, ігнорував гравця). Це «смертельна
> тріада», підсилена BPTT + вуликом. Лікування: **окрема нижча швидкість GRU**
> (`gruLearnRate=0.002` проти стекових `0.005`) + **тугіший кліп градієнта в часі**
> (`gruGradClip=0.5`) → спокійніші кроки, `maxQ` тримається пласко, `blind-chase` стабільно
> ~61% на сотнях тисяч кадрів. Проти злипання також помагає `pheromonesEnabled` (анти-стадність).

> Пряма лінія розвитку: **RNN (1997) → LSTM/GRU → Transformers** (attention =
> «памʼять без рекурсії, дивимось на все одразу»).

## Бій — шкода від удару на швидкості («кидок кобри»)

Шкодить **не дотик, а ЗБЛИЖЕННЯ на швидкості**. Міра — *closing speed*: проєкція
швидкості на напрямок до цілі (звичайний скалярний добуток). Асиметрично: шкоду
завдає той, хто **летить у** іншого.

| Ситуація | Результат |
|---|---|
| повільно зіштовхнулись | impact малий → **шкоди нема** |
| налетів на нерухомого | шкода лише жертві (перевага атакуючому) |
| лоб-у-лоб на швидкості | обидва отримали (реальний ризик атаки) |
| летять паралельно, торкнулись | impact ≈ 0 → нічого |

Ключове: **hit-and-run стає оптимальним математично**, а не тому, що ми його
запрограмували. Після удару швидкість витрачена → ти вразливий → відступ вигідний.

Поріг удару — **частка власного максимуму** (`impactSpeedFrac`) + абсолютна підлога.
Не абсолютне число: гравець у ~4 рази швидший за рій, тож єдиний поріг зробив би
його танком, а ворогів — безпечними. Плюс `impactInvuln` — кадри невразливості після
удару, інакше в купі агентів шкода йшла б **щокадру** (миттєва смерть).

Фракції (`Faction` + прапорець `friendlyFire`) вирішують, хто кому може шкодити —
фундамент під командні бої.

## Flow-field — pathfinding як ВХІД мережі

Рій **реактивний**: тисне в бік, де «відчуває» ціль, і тому б'ється об стіни — він
не знає лабіринту. Flow-field розв'язує це інакше (`flowfield.go`, клавіша `V`):

1. **BFS-хвиля від гравця** по прохідних клітинках → кожна знає **відстань до цілі**.
2. **Напрямок** = спуск градієнтом до сусіда з меншою відстанню (по 8 напрямках,
   із забороною зрізати кут крізь стіну).

Результат: у КОЖНІЙ точці карти є стрілка «туди до гравця крізь усі стіни».
Будується раз (~2500 клітинок ≈ мікросекунди, лише коли гравець змінив клітинку),
читається будь-якою кількістю агентів безкоштовно.

> **Головна ідея дизайну:** ми даємо це мережі **як ВХІД, а не як контролер**. Мозок
> не мусить розв'язувати лабіринт — навігація підказана, і вся ємність іде на
> **тактику** (коли кинутись, коли відступити). Свідомий поділ праці: те, що добре
> рахує алгоритм (BFS), не варто вчити градієнтним спуском.
> **Добрі фічі сильніші за більшу мережу.**

Коректність поля перевіряється не оком, а тестами (`flowfield_test.go`): інваріант
«стрілка веде на строго меншу відстань і не в стіну» + прохід за стрілками з КОЖНОЇ
клітинки до гравця.

## Вбивця — другий тип мозку (два вулики)

`ConfigKiller` (червоні) — мисливець, що **знає лабіринт** і **вчиться битися**.
Живе поруч із роєм у тому самому кадрі, тож різницю підходів видно наочно.

**Два незалежні вулики.** У кожного типу — своя спільна мережа і свій файл ваг
(`brain_weights.json` / `killer_weights.json`; `Net.file` памʼятає, куди зберігатись).
Тому зміна нагороди чи входів для вбивці **не чіпає** тонко налаштований рій — і той
лишається baseline-ом для порівняння.

**Що в нього інше:**

| | Рій | Вбивця |
|---|---|---|
| Навігація | реактивна, POMDP (`localSight`) | **flow-field** на вході, всевидющий |
| «Прогрес» | зближення по прямій | **рух уздовж коридору** |
| Нагорода | наближення + штрафи за стіни | **+ бойові члени** |

**Прогрес уздовж коридору — не деталь, а необхідність.** Спершу ми дали вбивці
flow-вхід, але лишили стару нагороду «зближення по прямій» — і він далі тикався в
стіни. Причина: обхід стіни **тимчасово збільшує пряму відстань**, тобто ми
**штрафували його саме за те, що він слухається поля**. Вхід і нагорода суперечили.

Виправлення (`progressToward`): для `flowNav`-мозку прогрес = **проєкція власної
швидкості на напрямок flow-field**. Чому саме проєкція, а не «відстань по лабіринту»:
та рахується в **клітинках** і міняється раз на ~20 кадрів → нагорода йшла б рваними
стрибками. Проєкція гладка, бо швидкість неперервна. Бонус: зникає шум від руху цілі
— агент оцінюється за **власні дії**. Ця ж величина живить і anti-stuck, щоб той не
сварив вбивцю саме за обхід.

**Бойова нагорода** (прапорець `CombatReward`) — поверх щільної:
```
+ rewardDamageDealt · завдана шкода
+ rewardDamageTaken · отримана        (від'ємний)
+ rewardKill        · вбивства
```
Щільне «наближайся» **веде** агента до цілі; бойові члени кажуть, **що робити, коли
він там**. Без щільної складової рідкісні події не вивчились би. Шкоду атрибутує
`resolveImpacts` у лічильники мозку, а споживає `rewardFor` наступного кадру — той
самий патерн «сигнал через кадр», що й `HitWall`.

> **Свідоме спрощення:** штраф за ВЛАСНУ смерть до буфера не потрапляє (агент гине й
> зникає, `Step` більше не викликається). Покладаємось на «− за отриману шкоду»:
> смерть = ти зібрав усі свої HP. Якщо вбивці почнуть самогубно лізти в розмін —
> знадобиться термінальний перехід.

**Склад поля бою** задає `unitRoster` (`pixel.go`): список типів, у кожного своє
поле `Count`. Прибрати тип = закоментувати рядок, додати новий = дописати рядок.

## Межа підходу (що досі НЕ вміє)

**Рій** (зелені) лишається принципово **реактивним**: навіть із памʼяттю GRU він не
будує маршрут по карті. Памʼять каже «куди він біг», але не «яким коридором його
обійти». Гравця, що глибоко сховався, рій знаходить радше **колективним покриттям**
(щільність + спільний мозок), ніж плануванням. Це не баг — це **baseline**, з яким
ми порівнюємо.

**Вбивця** (червоні) цю межу вже перетнув — flow-field дає йому маршрут. Але й у
нього лишаються межі:
- **не координується** з іншими (немає «оточити з двох боків» — кожен сам);
- **не моделює гравця** (не передбачає, куди той побіжить, крім грубого лідування
  за швидкістю цілі);
- **не памʼятає бою** довше за GRU-вікно (немає моделі «цей супротивник небезпечний»).

Наступні щаблі — командна координація й моделювання супротивника. Мапа — у
[ai-roadmap.md](ai-roadmap.md).

```go
sightRange  = 260.0   // [POMDP] радіус видимості гравця (localSight)
flowDistNorm = 60.0   // [ВБИВЦЯ] нормалізатор відстані по лабіринту (ФІКСОВАНИЙ!)

brainHidden1  = 32    // 1-й прихований шар (згин простору входів)
brainHidden2  = 16    // 2-й прихований шар (згин поверх згину)
brainActions  = 8     // напрямки руху = виходи Q
brainWhiskers = 8

// [RNN/GRU] рекурентна памʼять (useGRU)
gruHidden     = 32    // розмір прихованого стану h

seqBurnIn     = 4     // кадрів прогріву перед вікном (лише forward, warm-up h)
seqTotal      = 12    // = seqBurnIn + seqLen (усього кадрів у відрізку)
seqReplaySize = 512   // місткість буфера відрізків
seqBatch      = 8     // відрізків на кадр у навчанні
seqMinReplay  = 32    // поріг буфера, поки не вчимось
gruLearnRate  = 0.002 // ОКРЕМА (нижча за стек 0.005) швидкість — стабільність GRU
gruGradClip   = 0.5   // кліп градієнта в часі (тугіший = спокійніший BPTT)

qLearnRate = 0.005    // швидкість навчання
qGamma     = 0.95     // discount
qClip      = 10.0     // стеля TD-цілі

// Exploration (зараз ПОСТІЙНА; автоспад вимкнено в main.go)
qEpsilonConst = 0.01  // постійна ε
qEpsilonMax/Min/Decay = 0.30 / 0.03 / 25000   // якщо ввімкнути спад

// DQN-стабілізатори
qTargetSync = 1000 ; qReplaySize = 4096 ; qBatch = 16 ; qMinReplay = 200

// Reward — щільний (веде щокадру)
rewardCloserScale = 0.5 ; rewardWallHit = -1.0 ; rewardNearWall = -0.3

// [БІЙ] Reward — рідкісний (лише для мозків із CombatReward)
rewardDamageDealt = 2.0 ; rewardDamageTaken = -2.0 ; rewardKill = 5.0

// Anti-stuck (направлений вихід)
stuckHitInc = 4 ; stuckNoProgInc = 1 ; stuckLimit = 24 ; frustrationFrames = 24
stuckNearWall = 0.5 ; stuckProgressEps = 0.05

whiskerRange = 110.0 ; brainForce = 0.3 ; brainMaxWeight = 5.0
```

Феромони фрустрації і бойова фізика — у `main.go`:

## Збереження ваг

Ваги зберігаються при ESC / game over і вантажаться при старті (`SaveNet`/`LoadNet`).
`LoadNet` перевіряє записані розміри мережі (`inputs/hidden/actions`) — несумісна
архітектура → старт з нуля, без часткового завантаження. Target-мережа, буфер
досвіду й `age`/`stuckCounter` НЕ зберігаються (відновлюються наживо).

**По файлу на ТИП мозку.** `Net.file` памʼятає, куди зберігатись; `saveBrains`
дедуплікує мережі по вказівнику й пише кожну у свій файл. Ефемерні мережі
(`file == ""`, напр. мозок-жертва в self-play) не зберігаються взагалі.

> Зміна розмірів мережі (`brainHidden1/2`, `brainInputs`, `stackFrames`…) → старий
> `brain_weights.json` просто проігнорується як несумісний (навчання з нуля).

> **GRU:** ваги рекурентної клітини теж серіалізуються (`BrainData` містить стек W1..W3
> + GRU Wz..Bq з прапорцем `HasGRU`/`GruHidden`). Завантаження **зворотно сумісне**:
> старий файл без GRU-ваг вантажиться нормально, GRU при цьому ініціалізується з нуля
> (`initGRU`), а стек-ваги лишаються цілі. Розмір `h` (`gruHidden`) звіряється окремо.

## Що крутити для експериментів

| Константа | Ефект |
|---|---|
| `rewardNearWall` | Сильніший (−) → плавніший обхід, але обережніший у проходах |
| `rewardWallHit` | Сильніший штраф → обережніше зі стінами (може стати боягузом) |
| `qEpsilonConst` | Більше → хаотичніший/дослідник; менше → холодний мисливець |
| `stuckLimit` / `frustrationFrames` | Швидше/довше виходить із пасток |
| `whiskerRange` | Далі «бачить» стіни → раніше починає обходити |
| `qGamma` | Вище → довша «дальнозоркість», але менш стабільно |
| `sharedBrain` (main.go) | true = вулик (швидко вчиться, узгоджені «ключі»); false = незалежні особини |
| `pheromonesEnabled` (main.go) | стигмергія поверх будь-якого режиму: анти-стадність + пам'ять місця |
| `localSight` (main.go) | true = агент бачить гравця лише поблизу+по прямій (POMDP); false = всевидющий |
| `aiPlayer` (main.go) | true = self-play: гравцем керує мозок-жертва (вчиться тікати, co-evolution); false = людина |
| `stackFrames` | **памʼять** (стек-режим): 1 = реактивний (амнезик); 4 = стек кадрів. Зміна → скид ваг |
| `stackSkip` | вікно памʼяті в часі (кадрів між семплами історії) |
| `useGRU` (main.go) | **дефолт true** = рекурентна памʼять (GRU, вивчена, тримає курс довше); false = frame-stacking |
| `gruHidden` / `seqLen` | ємність рекурентної памʼяті / навчальне вікно BPTT (дужий вплив на навчання) |
| `seqBurnIn` | кадрів прогріву `h` перед вікном (більше = точніший стан, але важчий відрізок) |
| `gruGradClip` | кліп градієнта в часі: менше = стабільніше, але повільніше вчиться GRU |
| `Count` у конфізі (pixel.go) | скільки юнітів цього типу на полі; склад бою — `unitRoster` |
| `impactSpeedFrac` / `impactMinSpeed` | наскільки треба розігнатись, щоб удар зарахувався |
| `impactInvuln` / `playerMaxHP` | живучість: кадри невразливості й HP гравця |
| `rewardDamageDealt/Taken/Kill` | характер бійця: агресивний розмін ↔ обережний hit-and-run |
| `friendlyFire` (main.go) | true = свої шкодять своїм (рій проріджує себе) |
| `showFlowField` (main.go, клавіша V) | показати поле напрямків до гравця |

## Що далі

Жива мапа планів — у **[ai-roadmap.md](ai-roadmap.md)**. Найближче:
- **Командні бої** — юніти гравця проти вбивць (фракції вже є).
- **Респавн ворогів** — стала популяція = стабільні умови навчання й порівнювані метрики.
- **Термінальний перехід на смерть** — щоб штраф за загибель реально доходив до буфера.
- **Канал/актор** замість мютекса — той самий вулик ідіоматичним Go (CSP).
- Терміни — у [ai-glossary.md](ai-glossary.md).

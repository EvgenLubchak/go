# AI Brain: ворог-учень (v3 — Q-learning + whiskers)

## Що це

Ворог типу `ConfigLearner` (прапорець `IsLearner`, зелений) керується
**нейромережею, що вчиться сама через reinforcement learning (Q-learning)**.
У нього **немає вчителя** — ніхто не каже правильний рух. Агент діє, отримує лише
**reward** (нагороду/штраф) і сам відкриває стратегію: переслідувати гравця й
обходити стіни.

> **Важливо:** мозок вмикається прапорцем `IsLearner: true` у `EnemyConfig`, а
> НЕ міткою `Label` (мітка — лише для відображення). Це дозволяє назвати ворога
> як завгодно, не ламаючи навчання.

> Еволюція мозку:
> - **v1** — одношаровий перцептрон (лінійний, імітував chase-формулу).
> - **v2** — MLP + backprop, supervised: вчитель казав точну відповідь (перехоплення).
> - **v3** — Q-learning: вчителя немає, лише reward. Чесний шлях для обходу стін.

---

## Supervised vs Reinforcement Learning

```
supervised (v2):  "правильний рух = (0.83, 0.55)"   ← ми знаємо ціль
RL (v3):          "ти зробив дію 3 → отримав +0.5"  ← знаємо лише оцінку
```

Аналогія: ти не показуєш собаці, які м'язи напружити, щоб сісти — ти даєш
смаколик, коли вона сіла. Собака сама зв'язує дію з нагородою. Це і є RL.

## Архітектура (Q-мережа)

```
 state (13)            hidden (16)         Q-values (8)
  dx, dy, dist ──┐      ┌──◯──┐            Q[N]  ↑
  pVelX, pVelY ──┤      ├──◯──┤            Q[NE]
  whisker N    ──┼─ W1 ─►├──◯──┼─ W2 ─►   Q[E]   ← дія = argmax Q
  whisker NE   ──┤ +tanh ├──◯──┤ (лінійні) Q[SE]
  ... (8 шт.)  ──┘      └──◯──┘            ...
```

- Вхід — **стан** (13 чисел): куди гравець + 8 «вусів» (зір на стіни).
- Вихід — **8 Q-значень**, по одному на напрямок руху. Лінійні (не tanh), бо Q
  можуть бути будь-якими числами.
- **Дія** = напрямок з найбільшим Q (`argmax`).

---

## Стан (inputs)

```
[0] dx/screenWidth     напрямок до гравця X
[1] dy/screenHeight    напрямок до гравця Y
[2] dist/screenWidth   відстань до гравця
[3] pVelX/5            швидкість гравця X
[4] pVelY/5            швидкість гравця Y
[5..12] whiskers       близькість стіни у 8 напрямках  ◄── зір на перешкоди
```

### Whiskers (сенсори стін) — `wallWhisker`

8 променів з центру ворога у напрямках компаса (ті самі 8, що й дії). Кожен
крокує до стіни (`isWallAt`) і повертає **близькість**: `1` = стіна впритул,
`0` = чисто на всю довжину (`whiskerRange ≈ 140px ≈ 5 тайлів`). Так мережа
«бачить» перешкоду ще до зіткнення.

---

## Дії (actions)

8 напрямків руху за компасом (екранні координати, y вниз):

```
0=N(↑) 1=NE 2=E(→) 3=SE 4=S(↓) 5=SW 6=W(←) 7=NW
```

`dirs8[action]` — одиничний вектор; рух = `Acc += dirs8[action] · brainForce`.
Whisker[i] і action[i] дивляться в один бік → мережа бачить, наскільки
заблокований кожен напрямок, у який може піти.

---

## Reward (нагорода) — три складові

```
reward  = (prevDist − dist) · rewardCloserScale       // наблизився → +, віддалився → −
if hitWall:  reward += rewardWallHit                   // удар об стіну (РІДКИЙ сигнал)
reward += rewardNearWall · whisker[обраний напрямок]   // близькість стіни (ЩІЛЬНИЙ сигнал)
```

**Рідкий vs щільний штраф за стіни** — ключова ідея:

| Сигнал | Коли | Навіщо |
|---|---|---|
| `rewardWallHit = -1.0` | лише в момент **удару** | груба ознака «так не можна» |
| `rewardNearWall = -0.3` | **щокадру**, ∝ близькості стіни попереду | плавний градієнт «тримай дистанцію» |

Аналогія: `rewardWallHit` каже «погано» лише коли ти **врізався**; `rewardNearWall`
— стіна «гріється» в міру наближення, тож агент **завертає заздалегідь**. Щільний
сигнал дає мережі градієнт, по якому вона вчиться **плавно обходити**, а не
довбати стіну (звідси «течуть як вода»). Прогрес до гравця (+) перебиває
proximity-штраф у проходах, тож щілини агент усе одно використовує.

> Reward shaping загалом: замалий reward тоне в шумі (мережа не вчиться),
> завеликий — дестабілізує. Масштаби підібрані так, щоб «хороший» кадр давав ~0.5.

## Навчання: Q-learning + рівняння Беллмана — `tdUpdate`

Q(s, a) = «наскільки хороша дія a у стані s» = очікувана сумарна майбутня
нагорода. Оновлюємо за **рівнянням Беллмана**:

```
target  = reward + γ · max_a' Q(nextState, a')   ← ціль
tdError = target − Q(state, action)              ← наскільки помилились
```

Далі — звичайний backprop `tdError`. **Тільки** для дії, яку реально зробили
(лише про неї маємо reward); інші виходи не чіпаємо.

`γ` (discount) розв'язує **credit assignment** (хто винен за відкладену
нагороду): цінність *просочується назад* у часі, крок за кроком.

---

## Три стабілізатори DQN (чому онлайн нейро-Q-learning без них падає)

Нейромережа + бутстреп (ціль залежить від самої мережі) + кореляція даних =
«смертельна тріада». Без захисту агент **колапсує** в одну й ту саму дію. Три
прийоми з DQN роблять навчання надійним:

| Прийом | Проблема, яку лікує | Як |
|---|---|---|
| **Target network** | Ціль `max Q(s')` тікає з кожним кроком (мережа женеться за хвостом) | Окрема ЗАМОРОЖЕНА копія ваг (`tW1/tW2…`) рахує ціль; синхронізуємо раз на `qTargetSync` |
| **Experience replay** | Сусідні кадри майже однакові → перенавчання на свіже, забування старого | Кільцевий буфер переходів; щокадру вчимось на ВИПАДКОВІЙ вибірці (`qBatch`) |
| **Error clipping** | Рідкісна велика похибка → велетенський стрибок ваг | `tdError` обрізаємо до `[-1, 1]` (Huber-подібно) |

Тест `TestQLearningChasesNoWalls` стабільно проходить (узгодженість дії з
напрямком до гравця 0.7–1.0 на десятках запусків).

## Anti-stuck — вихід із пасток

Навчання не ідеальне: іноді агент застрягає (б'ється в стіну або притиснутий у
куті). Механізм «фрустрації» — **рятівна сітка** поверх навчання:

**Два тригери застрягання** (накопичуються в `stuckCounter`):
1. **удар об стіну** (`hitWall` → `+stuckHitInc`);
2. **притиснутий до стіни без прогресу** (`maxWhisker ≥ stuckNearWall` і дистанція
   до гравця не зменшується → `+stuckNoProgInc`).

**Направлений вихід** — коли `stuckCounter ≥ stuckLimit`, на `frustrationFrames`
кадрів вмикається фрустрація: агент іде в **найвідкритіший бік** (`escapeAction`
обирає whisker з найменшою близькістю стіни), а не смикається випадково. Серед
однаково відкритих напрямків — рівноймовірно (щоб агенти не злипались в один бік).

> ⚠️ Це **сітка безпеки, а не лікування**. З майже нульовою ε жадібна політика
> може повести агента назад у ту саму кишеню. Справжнє лікування — щоб мережа
> *вивчила* не лізти туди (це робить `rewardNearWall` з часом).

---

## Феромони фрустрації (стигмергія)

Друга «сітка безпеки» — колективна пам'ять рою. Це **не** pathfinding (мозок так
само не знає мапи), а комашина **стигмергія**: агенти лишають у середовищі сліди, і
рій сам обтікає глухі місця.

- **Deposit** — коли учень ОФІЦІЙНО застряг (`markStuck` при спрацюванні фрустрації),
  у його клітинку сітки `g.frustration` додається `frustrationDeposit`. Саме при
  застряганні, а **не** на кожен дотик стіни — інакше виходив би «слимачий слід»
  уздовж усіх стін.
- **Decay** — щокадру вся сітка множиться на `frustrationDecay` (<1), тож «погане
  місце» з часом забувається й знову стає прохідним.
- **Repulsion** — у `calcAcceleration` учень читає сліди навколо (`frustrationForce`,
  радіус `frustrationRadius`) і отримує силу геть від них (× `frustrationRepel`).

Ефект: коли рій пілиться в куті — клітинки наливаються слідом → агентів виштовхує
назовні → вони розповзаються шукати інші входи. Один застряг — попередив усіх.
Емерджентний обхід з флангів, як у мурах.

> **Перемикач:** `pheromonesEnabled` (main.go) вмикає/вимикає всю стигмергію
> (deposit + repulsion + теплокарту). `false` → чистий Q-learning + whiskers +
> індивідуальний anti-stuck, без колективної пам'яті — для порівняння поведінки.

> Чому захардкоджено, а не вивчено: користь сліду надто відкладена в часі (уникнув →
> рій розповзся → хтось знайшов вхід → спіймав), а короткозорий реактивний агент
> такий довгий причинний ланцюг не вловить. Хардкодимо те, що знаємо й що RL не
> витягне дешево.

## Exploration: ε (постійна + опційний автоспад)

`ε-greedy`: з імовірністю ε — випадкова дія (дослідження), інакше `argmax Q`.

- **За замовчуванням ε ПОСТІЙНА** = `qEpsilonConst` (перемикач
  `epsilonDecayEnabled = false` у `main.go`). Стабільний рівень дослідження весь час.
- **Опційний автоспад** (`epsilonDecayEnabled = true`): ε лінійно спадає
  `qEpsilonMax → qEpsilonMin` за `qEpsilonDecay` кроків (поле `age` лічить кроки).
  Свіжий мозок багато досліджує → з часом стає мисливцем, але не нижче floor.
  Завантажений мозок стартує одразу на floor (`age = qEpsilonDecay`) — вже навчений.

## Цикл кадру (інтеграція)

```
Update() → calcAcceleration()  (Brain != nil):
    1. state := GatherInputs(e, player)         // + whiskers
    2. action := Brain.Step(state, dist, HitWall)
         ├─ reward за минулу дію (наблизився? врізався? близько стіни?)
         ├─ remember(перехід) у буфер
         ├─ trainBatch(): qBatch випадкових переходів → tdUpdate
         ├─ оновити stuckCounter (anti-stuck)
         └─ обрати дію: фрустрація(escapeAction) / ε-greedy
    3. Acc += dirs8[action] · brainForce
         → updateEnemies(): рух, відбивання, виставити HitWall
```

### Паралелізм: горутини й безпека пам'яті

`calcAcceleration` рахується **паралельно** воркер-пулом: `runtime.NumCPU()` горутин
(`sync.WaitGroup` + `wg.Wait()`), кожна обробляє свій шматок ворогів `[start:end)`.
Це тримає 50–500 ворогів × (boids + мозок + whiskers + феромони) у 120 FPS.

Безпека пам'яті — **без жодного мютекса**, через розділення на фази:

| Дані | Читання (паралельно) | Запис (однопотоково) |
|---|---|---|
| `boidMap` | calcAcceleration | updateBoidMap |
| `frustration` | calcAcceleration (`frustrationForce`) | updateEnemies (deposit + `decayFrustration`) |
| `enemies[i].Acc`, `Brain` | — | кожен елемент пише ОДНА горутина (свій chunk) |

Читання й запис рознесені в часі бар'єром `wg.Wait()`, а одночасні читання в Go
безпечні (гонка лише при одночасному записі). Тому `mu sync.Mutex` у `Game` досі не
потрібен. Принцип: **«всі читають → потім один пише» замість локів.**

## Візуалізація (`render.go`)

Для Learner-а малюються:
- **8 променів** (`showWhiskers`) — довжина = вільний простір, колір від зеленого
  (чисто) до червоного (стіна близько);
- **жовта стрілка** — напрямок дії, яку мережа щойно обрала;
- **теплокарта феромонів** (`showFrustration`) — помаранчевий шар під ворогами,
  яскравість ∝ силі сліду «тут застрягали».

## Межа підходу: реактивність vs пошук шляху

Важливо розуміти, **що цей мозок уміє, а що — ні**.

Агент **реактивний**: бачить лише напрямок до гравця + 8 коротких вусів (≈5 тайлів),
**без карти й без пам'яті**. Тому:

- ✅ **локальний обхід** — обійти одну-дві стіни на шляху до гравця;
- ❌ **глобальна навігація** — знайти гравця, що сховався в куті за купою стін.
  Це потребує тимчасово йти ГЕТЬ від гравця крізь лабіринт, пам'ятаючи маршрут —
  тобто **пошук шляху (pathfinding)**, а не реакцію.

> **Реактивний обхід ≠ пошук шляху.** Жоден reward цього не дасть — це межа
> підходу «короткі вуса без пам'яті». Кути за стінами лишаються **безпечними
> сховками** (зараз — стелс-механіка).

Майбутнє рішення — **flow-field** (BFS/Dijkstra від гравця): кожен тайл знає
напрямок до гравця з урахуванням усіх стін → агенти знаходять гравця будь-де.
Деталі — у [ai-roadmap.md](ai-roadmap.md).

```go
brainInputs   = 13    // 5 базових + 8 whiskers
brainHidden   = 16    // нейрони прихованого шару

qGamma     = 0.9      // discount
```

## Збереження ваг

Ваги зберігаються при ESC / game over і вантажаться при старті. `LoadBrain`
перевіряє записані розміри мережі (`inputs/hidden/actions`) — несумісна
архітектура → старт з нуля, без часткового завантаження. Target-мережа, буфер
досвіду й `age`/`stuckCounter` НЕ зберігаються (відновлюються наживо).

> Зміна `brainHidden`/`brainInputs`/`brainActions` → видали `brain_weights.json`
> (або він просто проігнорується як несумісний).

## Що крутити для експериментів

| Константа | Ефект |
|---|---|
| `rewardNearWall` | Сильніший (−) → плавніший обхід, але обережніший у проходах |
| `rewardWallHit` | Сильніший штраф → обережніше зі стінами (може стати боягузом) |
| `qEpsilonConst` | Більше → хаотичніший/дослідник; менше → холодний мисливець |
| `stuckLimit` / `frustrationFrames` | Швидше/довше виходить із пасток |
| `whiskerRange` | Далі «бачить» стіни → раніше починає обходити |
| `qGamma` | Вище → довша «дальнозоркість», але менш стабільно |
